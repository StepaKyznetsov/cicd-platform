CI/CD Pipeline

Полный цикл автоматизации: от коммита до продакшена

Этапы пайплайна

1

📝 Commit & Push

Разработчик пушит код в репозиторий

git push commit
2

🔨 Build

Автоматическая сборка приложения

npm build docker build
3

🧪 Test

Запуск всех типов тестов

unit tests integration e2e
4

📦 Package

Упаковка и версионирование

docker push versioning
5

🚀 Deploy

Развертывание на окружениях

staging production

Пример GitHub Actions конфигурации 

name: CI/CD Pipeline

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

env:
  NODE_VERSION: '18'
  DOCKER_IMAGE: 'myapp'

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: ${{ env.NODE_VERSION }}
          
      - name: Install dependencies
        run: npm ci
        
      - name: Run tests
        run: npm test
        
      - name: Build application
        run: npm run build
        
  docker:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - name: Build Docker image
        run: docker build -t ${{ env.DOCKER_IMAGE }} .
        
      - name: Push to registry
        run: docker push ${{ env.DOCKER_IMAGE }}
        
  deploy:
    needs: docker
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to production
        run: kubectl apply -f k8s/

Лучшие практики CI/CD

✅ Держите пайплайн быстрым

Каждый этап не должен занимать более 10 минут. Используйте кэширование и параллельные задачи.

✅ Используйте проверки безопасности

Интегрируйте SAST, DAST и сканирование зависимостей на ранних этапах.

✅ Внедрите автоматический откат

При сбое деплоя автоматически откатывайтесь к предыдущей стабильной версии.

✅ Логируйте всё

Централизованное логирование всех этапов для быстрой отладки проблем.
